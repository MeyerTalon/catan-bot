# AWS infrastructure (Terraform)

Runs the Catan app on AWS: Cognito (auth), ECS Fargate behind an ALB (FastAPI), RDS Postgres, and S3 + CloudFront (React). CloudFront also proxies `/api/*` to the ALB, so the whole app has one HTTPS hostname and no CORS. Diagram, per-resource cost (~$44/month idle), and what is deliberately left out: [ARCHITECTURE.md](ARCHITECTURE.md).

## Layout

```
terraform/
├── bootstrap/        one-time per AWS account: state bucket, GitHub OIDC provider, terraform-apply role, budget (local state)
├── modules/          reusable building blocks, no environment knowledge
│   ├── network/      VPC, 2 public subnets, IGW
│   ├── database/     RDS Postgres (single-AZ, private) + SSM parameter with DATABASE_URL
│   ├── auth/         Cognito user pool + app client
│   ├── backend-service/  ECR, ECS Fargate (1 task), ALB, IAM, logs
│   ├── static-site/  S3 + CloudFront (OAC, SPA fallback, /api/* → ALB)
│   └── deploy-role/  least-privilege GitHub Actions role for app deploys
├── envs/prod/        composes the modules; sizing in locals; remote state
├── Makefile          init/plan/apply/check wrappers
└── .tflint.hcl
```

| Stack | State | Applied by | Changes |
|---|---|---|---|
| `bootstrap/` | local file | a human, once | almost never |
| `envs/<env>/` | S3 (bootstrap bucket) | CI on `main`, or a human | whenever infra changes |
| app code | n/a | CI via `deploy-role` | every merge |

The only secret is the RDS password: generated by Terraform, stored as an SSM SecureString, injected into the task as `DATABASE_URL`. It is also in the (encrypted, versioned) state file — treat state-bucket access as production access.

## Prerequisites

- Terraform **>= 1.10** (`brew install hashicorp/tap/terraform`)
- AWS CLI with admin-capable credentials in `~/.aws/credentials` or env vars — never in the repo. Check with `aws sts get-caller-identity`.
- Docker
- Optional: `tflint` for `make lint`

## First-time setup

### 1. Bootstrap the account

```bash
cd terraform/bootstrap
cp terraform.tfvars.example terraform.tfvars   # set github_repository and budget_alert_email
terraform init
terraform apply
```

Keep `bootstrap/terraform.tfstate` somewhere safe (no secrets, but losing it means importing later).

### 2. Point the environment at the state bucket

Replace `<ACCOUNT_ID>` in `envs/prod/backend.hcl` with the value from `terraform output state_bucket`. Commit it.

### 3. Create the environment (two passes)

ECS cannot start without an image, so create the registry first:

```bash
cd terraform
make init ENV=prod
terraform -chdir=envs/prod apply -target=module.backend.aws_ecr_repository.this
```

Build and push from the repo root:

```bash
ECR=$(terraform -chdir=terraform/envs/prod output -raw ecr_repository_url)
aws ecr get-login-password --region us-west-2 | docker login --username AWS --password-stdin "${ECR%%/*}"
docker build --platform linux/amd64 -f backend/Dockerfile -t "$ECR:latest" .
docker push "$ECR:latest"
```

Then everything else (RDS takes several minutes; CloudFront a few more):

```bash
make plan ENV=prod
make apply ENV=prod
```

**Migrations run in the container.** `backend/Dockerfile` (built from the repo root so it includes `db/`) runs `alembic upgrade head` before `uvicorn`; the task is the only thing with a network path to RDS, and the ECS health-check grace period is 120 s to allow for it.

### 4. Check

```bash
OUT="terraform -chdir=terraform/envs/prod output -raw"
curl "$($OUT backend_url)/health"        # via CloudFront → ALB → task
```

Logs: `aws logs tail "$($OUT log_group_name)" --follow`.

### 5. Build and publish the frontend

From `frontend/`:

```bash
export VITE_BACKEND_URL="$(terraform -chdir=../terraform/envs/prod output -raw backend_url)"
npm run build
aws s3 sync dist/ "s3://$(terraform -chdir=../terraform/envs/prod output -raw frontend_bucket)" --delete
aws cloudfront create-invalidation \
  --distribution-id "$(terraform -chdir=../terraform/envs/prod output -raw cloudfront_distribution_id)" --paths "/*"
```

Open `$($OUT frontend_url)`.

### 6. Wire up GitHub Actions

Nothing deploys on push. `ci.yml` (checks only, no AWS) runs on pull requests and on `main`; everything that touches AWS is a manually dispatched workflow that runs inside a GitHub **environment**, and the IAM roles trust those environments via OIDC (`sub = repo:<owner/repo>:environment:<name>`). No AWS keys go in GitHub.

Create two environments (Settings → Environments):

| Environment | Deployment branches | Required reviewers | Used by |
|---|---|---|---|
| `production` | `main` only | yes (you) | `deploy-backend.yml`, `deploy-frontend.yml`, `deploy.yml`, the **apply** job of `terraform.yml` |
| `production-plan` | `main` only | no | the **plan** job of `terraform.yml` (so the plan runs without approval and you approve the apply after reading it) |

Then set these **environment variables** (none are secret) on `production`; the two `AWS_*` ones also on `production-plan`:

| Variable | Value from |
|---|---|
| `AWS_REGION` | `us-west-2` |
| `AWS_TERRAFORM_APPLY_ROLE_ARN` | `bootstrap` output `terraform_apply_role_arn` (both environments) |
| `AWS_DEPLOY_ROLE_ARN` | `envs/prod` output `github_deploy_role_arn` |
| `ECR_REPOSITORY` | `ecr_repository_url` |
| `ECS_CLUSTER` | `ecs_cluster_name` |
| `ECS_SERVICE` | `ecs_service_name` |
| `FRONTEND_BUCKET` | `frontend_bucket` |
| `CLOUDFRONT_DISTRIBUTION_ID` | `cloudfront_distribution_id` |
| `VITE_BACKEND_URL` | `backend_url` (`https://<cloudfront>/api`) |

Workflows (Actions tab → Run workflow):

| Workflow | What it does |
|---|---|
| **Terraform** | `plan` (default) or `plan-and-apply` for `terraform/envs/prod`. The plan lands in the job summary; the apply job waits for your approval on `production` and applies exactly that plan file. |
| **Deploy backend** | builds the image, pushes `:<sha>` (tags are immutable), registers a new task definition revision with it (cloning the latest one, so env/secret changes from Terraform ride along), points the service at it, waits until stable. Migrations run in the container. Needs the `ECS_TASK_FAMILY` variable (`ecs_task_family` output). |
| **Deploy frontend** | builds with `VITE_BACKEND_URL`, syncs S3, invalidates CloudFront. |
| **Deploy all** | backend, then frontend. |

The deploy role can push images, roll the service, and sync the frontend — nothing else; the apply role is admin but only usable from those two environments.

## Day-to-day

```bash
cd terraform
make check                 # fmt -check + validate every stack/module (no AWS access needed)
make lint                  # tflint, if installed
make plan ENV=prod         # writes envs/prod/tfplan
make apply ENV=prod        # applies that plan
make output ENV=prod ARGS="-raw backend_url"
```

Deploy new backend code without Terraform: run the **Deploy backend** workflow. It is the only thing that should change the running task definition — the ECS service ignores `task_definition` drift, so a Terraform change to the task's env or secrets takes effect on the next deploy, not on apply. Rotate the CloudFront→ALB secret with `make plan ENV=prod ARGS="-replace=module.backend.random_password.origin_verify[0]"` (the distribution update takes a few minutes; the ALB answers 403 to anything without the header).

Pause the database when idle: `aws rds stop-db-instance --db-instance-identifier catan-prod-postgres` (AWS restarts it after 7 days; the task will fail health checks until it is back).

## Adding an environment

1. `cp -r envs/prod envs/staging`; in `main.tf` set `environment = "staging"`, `deletion_protection = false`, `skip_final_snapshot = true`, `force_destroy = true`.
2. In `envs/staging/backend.hcl` set `key = "envs/staging/terraform.tfstate"`.
3. `make init ENV=staging && make plan ENV=staging`. The workflows are hard-wired to `prod`/`production`; a second env needs its own copy of `terraform.yml` (and deploy workflows) pointing at `envs/staging` and a `staging` GitHub environment, plus a `github_environments` entry on the roles.

Each environment is its own VPC and state file; only the bootstrap bucket and OIDC provider are shared. A second env roughly doubles the bill.

## Destroy

```bash
cd terraform
make destroy ENV=prod
```

Prod defaults protect data: RDS `deletion_protection = true` / `skip_final_snapshot = false`, Cognito `deletion_protection = true`, frontend bucket `force_destroy = false`. Flip them in `envs/prod/main.tf`, apply, then destroy. The bootstrap bucket has `prevent_destroy`; empty and delete it by hand if you leave the account.
